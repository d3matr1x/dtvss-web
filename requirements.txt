# Application-layer encryption for customer database (Tier 2, ADR D14).
# Records in customers.json are stored as Fernet ciphertext rather than
# plaintext on the Railway volume. Defends against anyone with read access
# to the volume but not the CUSTOMERS_ENCRYPTION_KEY env var (Railway
# employees, account compromises that don't reach the running Flask
# process, backups restored to a wrong context). Does NOT defend against
# code execution inside the Flask process itself.
#
# Version pin rationale:
#   - `cryptography` is from the PyCA / OpenSSL team and follows strict
#     semver; the lockfile (requirements-lock.txt) pins the exact version
#     with hashes for supply-chain integrity.
#   - >= 46.0.5 because CVE-2026-26007 (high severity, CVSS 8.2) affects
#     all earlier versions in our intended range (42-45). The CVE is a
#     subgroup-validation bug in SECT (binary) elliptic curves. DTVSS
#     itself is not exploitable by this because Fernet uses symmetric
#     crypto (AES-128-CBC + HMAC-SHA256) and we don't touch SECT curves,
#     but the CI policy correctly blocks adding a known-vulnerable
#     dependency regardless of whether we call the affected functions.
#   - < 47 to allow patch updates within 46.x but require a deliberate
#     review for the next major.
cryptography>=48.0.0,<49

# Dependency pin rationale (per Fix #7 in PATCHES_v2.md):
#
#   flask==3.1.3      — CVE-2026-27205: missing Vary: Cookie header on
#                        some session access patterns. DTVSS has no
#                        sessions today, but the fix is free.
#
#   flask-cors==6.0.2 — CVE-2024-6839, CVE-2024-6844, CVE-2024-6866:
#                        three CORS path-matching bugs (case-insensitive
#                        match, '+' decoded to space, longer-pattern
#                        precedence). DTVSS uses flask-cors as its origin
#                        allowlist, so these directly affect us.

# Redis backend for Flask-Limiter on Railway (RAIL-02).
# Railway's private networking is IPv6; redis>=5.0 handles this natively.
# If REDIS_URL isn't set, Flask-Limiter falls back to memory:// (per-worker,
# resets on restart) — safe for local dev, not production.
redis>=5.0.0

# urllib3 — DNS-pinned HTTPS for SSRF guard in security.py.
# The stdlib urllib.request does its own DNS resolution at connection time,
# which left a TOCTOU window between validate_external_url's resolution and
# urlopen's connect. CodeQL alert #20 (py/partial-ssrf) flagged this.
# urllib3.connection.HTTPSConnection takes server_hostname (SNI) and
# assert_hostname (cert validation) as separate kwargs, so we connect to
# the validator-returned IP while TLS still validates against the hostname.
urllib3==2.7.0          # CVE-2026-21441/44432: decompression-bomb fix
